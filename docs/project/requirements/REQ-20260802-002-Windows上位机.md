# REQ-20260802-002 Windows上位机软件

状态：In Progress  
优先级：P0  
提出日期：2026-08-02  
目标版本：PC Tool V1.0

## 1. 原始需求

根据当前USART2二进制协议制作可在普通电脑使用的EXE上位机。选择COM口并连接后，软件自动发送00唤醒设备；用户可勾选Pitch和Roll持续查看数据。界面参考用户提供的传感器上位机截图，采用多个页面，每页负责不同功能。USART2串口通信指令手册中能够实现的功能均应提供图形化操作。

## 2. 当前事实

- 当前设备维护口为USART2，115200、8-N-1、无流控。
- Stop1通信必须执行单字节00、等待FF READY、再发送完整命令帧。
- 当前协议支持GET_STATUS、RUN_REPORT、SET_CONFIG、READ_QUEUE、CLEAR_QUEUE、SLEEP、MODEM_ON、MODEM_OFF、GET_IMU_DIAG、SET_MOUNT、GET_PITCH、GET_ROLL、GET_ANGLE和GET_IMU_LIVE。
- 当前协议不提供原始三轴加速度、三轴角速度或Yaw数据。
- 当前PC环境为Windows x64，已安装Python 3.13和pyserial；尚未安装PySide6和PyInstaller。
- 要做到目标电脑无Python环境也能运行，需要将运行时、GUI库和串口库一起打包。

## 3. 推荐技术路线

采用 Python + PySide6 + pyserial + PyInstaller：

- PySide6适合制作接近参考图片的现代多页面桌面界面。
- 串口收发放在独立工作线程，GUI线程不等待串口，避免窗口卡死。
- 所有协议帧由统一的ProtocolCodec生成和校验，不在按钮事件里硬编码CRC。
- 使用单请求队列和Sequence匹配，严格执行一问一答。
- V1.1实时页面使用GET_IMU_LIVE，一次读取加速度、角速度、Pitch和Roll；旧固件仍可用GET_ANGLE读取角度。
- 发布为Windows x64免安装版本，目标电脑不需要Python。
- 开发版本先使用onedir目录便于诊断，验收后再生成onefile单EXE。

预计单文件EXE体积约80~150 MB，首次启动可能需要数秒解压。最终大小以实际打包结果为准。

## 4. 建议页面

### 4.1 连接与总览

- 自动扫描和刷新COM口。
- 显示端口描述、USB VID/PID和当前连接状态。
- 点击连接后自动执行00 → READY。
- 自动重试唤醒并显示明确失败原因。
- 展示电池电压、4G状态、低压熔断、事件数量、IMU状态和最近上报结果。

### 4.2 实时角度

- Pitch、Roll独立勾选。
- 勾选任意一项后周期发送GET_ANGLE。
- 默认100 ms，可设置50~2000 ms。
- 大字体实时数值、角度仪表和滚动趋势曲线。
- 连接中断时停止轮询，不继续堆积请求。
- 可选CSV记录：时间、Pitch、Roll、连接状态。
- 可选二维或三维姿态示意；只有Pitch/Roll，没有真实Yaw。

### 4.3 参数设置

- Wake-Up阈值、倾角阈值、RTC周期、低压阈值。
- 安装零度方向Z+/Z-/X+/X-/Y+/Y-。
- 输入范围验证、发送前确认、成功/失败提示。
- 设置后自动GET_IMU_DIAG进行读回核对。

### 4.4 状态与诊断

- 完整解析GET_STATUS的63字节数据。
- 复位原因、上报阶段、失败原因转换为中文。
- 显示串口丢帧、半帧超时、UART错误和RTC/IMU计数。
- GET_IMU_DIAG关键寄存器支持十六进制与解释视图。

### 4.5 事件队列

- 读取0~2号事件。
- 将52字节EventRecord解析为表格。
- 支持刷新、CSV/JSON导出。
- CLEAR_QUEUE需要二次确认并提示低电压限制。

### 4.6 4G与上报

- ML307C开机、关机。
- 人工RUN_REPORT。
- 显示任务已接受、BUSY和失败状态。
- 上报期间周期查询状态需要避开BUSY阶段，不能阻塞串口请求队列。

### 4.7 串口调试与日志

- 时间戳、方向、功能码、Sequence、状态和原始Hex日志。
- 支持发送合法的自定义协议帧。
- CRC自动生成、响应CRC校验。
- 日志筛选、清空和导出。
- 默认隐藏危险操作，避免误清队列或误休眠。

### 4.8 关于与协议

- 软件版本、协议版本、固件兼容范围。
- 内置快速测试说明和状态码表。
- 链接到USART2串口通信指令手册。

├─ tests/
├─ requirements.txt
├─ build_exe.ps1
└─ README.md
~~~

关键状态机：

~~~text
Disconnected
  → PortOpen
  → SendWake00
  → WaitReady
  → Ready
  → SendOneRequest
  → WaitMatchingResponse
  → Ready
~~~

断开、超时、CRC错误或拔线会进入Recovering；实时轮询只能存在一条在途请求，防止串口阻塞和响应错配。

## 7. 已确认结论

1. 仅支持Windows 10/11 x64，不考虑Windows 7和32位系统。
2. 最终交付采用免安装单文件EXE；开发和诊断阶段同时保留便携目录版。
3. V1包含Pitch/Roll数值、滚动趋势曲线和简化3D板卡姿态。
4. 实时角度默认100 ms轮询，允许用户调整。
5. V1严格使用现有USART2协议，不修改STM32固件。
6. 六轴页面保留界面和协议扩展提示，等后续增加GET_IMU_RAW后启用。
7. 软件暂定名称为“Solar IMU 工业监测上位机”，后续可只改品牌资源而不改变架构。

## 9. 风险

- PySide6单文件体积较大，杀毒软件可能对未签名的新EXE产生信誉提示。
- 单文件模式启动比目录模式慢，调试阶段优先使用目录模式。
- 100 ms轮询会让设备持续处于维护窗口，不会进入Stop1，这是用户主动实时监视时的预期行为。
- 上报期间固件返回BUSY，上位机必须退避而不是高频重试。
- 现有协议没有设备固件版本查询，软件暂时只能按协议V1判断兼容性。

## 12. V1.0.1 CH340连接修复

- 打开串口前预置DTR/RTS为低，避免pyserial默认拉高控制线与XCOM行为不同。
- 串口打开后等待300 ms让CH340和Windows驱动稳定，所有写操作增加flush。
- 唤醒从固定3次、每次2秒改为6次自适应间隔，更适合Stop1首字节牺牲和GPIO转UART的时序。
- 同时识别二进制READY、`[SYS] UART WAKE READY`和`[SYS] Ready`文本兼容响应。
- READY丢失时自动发送Sequence为FE的GET_STATUS探测；收到合法响应也可确认链路就绪。
- 失败提示包含最后64字节RX原始Hex，不再被通用“串口已断开”覆盖。
- 修复连接失败后工作线程已销毁但客户端仍持有引用导致的再次连接异常。
- 新增3项唤醒兼容性测试，总计11项测试通过。
